# Вводный практикум по n8n: от узлов до циклов

**Цель:** научиться самостоятельно читать и собирать workflow: запускать по событию, получать данные из предыдущих узлов, сравнивать значения, обрабатывать несколько элементов и обращаться к API. Практикум не содержит готового решения основного ДЗ.

**Время:** около 70–90 минут для обязательных упражнений; дополнительные эксперименты можно пропустить. Программирование на JavaScript не требуется.

## Подготовка (5 минут)

1. Запустите `docker compose up -d`, откройте `http://localhost:5678`.
2. Создайте в n8n **три отдельных workflow**, последовательно импортируя файлы:
   - `workflows/tutorial-basics.json` — *Tutorial 01 — Данные, условия и HTTP*;
   - `workflows/tutorial-items-loops.json` — *Tutorial 02 — Items и циклы*;
   - `workflows/tutorial-webhook.json` — *Tutorial 03 — Webhook и HTTP-ответ*.
3. Не путайте их с `workflows/student-starter.json`: это заготовка для основного задания, ее пока не трогаем.
4. Начинайте с первого workflow. **Sticky Notes** — это текстовые пояснения, они не выполняются как операции.

> Интерфейс может немного меняться. В репозитории закреплена версия n8n через `compose.yaml`. При работе следите за панелями **Input / Output**, выбранным входным item и режимом **Fixed / Expression**.

## 1. Справочник узлов: что для чего использовать (10 минут)

Узел (**node**) — один шаг процесса. Узлы делятся по назначению, а не по сложности.

| Группа | Узел | Задача | Где потренируемся |
|---|---|---|---|
| Запуск | **Manual Trigger** | Ручной запуск | Практикум 01 и 02 |
| Запуск | **Webhook** | Получить HTTP-запрос, включая JSON | Практикум 03 |
| Запуск | **Schedule Trigger** | Запустить workflow по расписанию | Обзор и необязательный опыт |
| Запуск | **Error Trigger** | Запустить отдельный workflow по событию ошибки | Обзор, необязательный опыт |
| Работа с данными | **Edit Fields (Set)** | Создать/переименовать поля, сформировать JSON | Практикум 01, 02 и 03 |
| Ветвление | **If** | Разделить по условию на true и false | Практикум 01 и 02 |
| Ветвление | **Switch** | Выбрать одну из нескольких веток | Практикум 01 |
| Интеграция | **HTTP Request** | Вызвать REST API, получить ответ | Практикум 01 |
| Управление потоком | **Loop Over Items** | Обработать данные последовательными порциями | Практикум 02 |
| Ответ | **Respond to Webhook** | Вернуть HTTP-код и JSON вызывающей стороне | Практикум 03 |
| Дополнительно | **Wait**, **Merge**, **Filter**, **Code** | Пауза, объединение, отбор, свой код | Краткий обзор ниже |

**Важно:** `Manual Trigger`, `Webhook` и `Schedule Trigger` — не три последовательных действия. Это **альтернативные способы запустить** workflow. Для учебного примера используем отдельные схемы, чтобы не путать события запуска.

**Задание:** объясните своими словами, в чем разница между **триггером**, **действием** и **условием**. Найдите эти три типа узлов на схеме Tutorial 01 или Tutorial 03.

## 2. Как устроены данные: item, JSON и Input/Output (10 минут)

В n8n данные обычно передаются **элементами (items)**. Каждый item имеет поле `json` — объект с данными. Например, два item могут выглядеть так:

```json
[
  {"json": {"userId": 451, "priority": "high"}},
  {"json": {"userId": 452, "priority": "low"}}
]
```

Это **два отдельных item**, а не один item со списком. При просмотре одного элемента в интерфейсе вы обычно видите его содержимое `{ "userId": ... }`, а не служебную оболочку.

Узел получает Input, выполняет операцию и формирует **свой Output**. Результат узла не обязан содержать все предыдущие поля.

**Эксперимент 2.1:** запустите Tutorial 01 кнопкой **Execute workflow**. Откройте `Example input`: сколько элементов и какие поля вышли? Откройте `Get demo user`: какие поля изначального обращения отсутствуют в его Output?

**Эксперимент 2.2:** поменяйте `priority` на `medium`; пройдите по подсвеченной ветке If. Верните `high`.

## 3. Expressions и доступ к переменным предыдущих узлов (15 минут)

В n8n нет «одной общей переменной для всего workflow». Поля принадлежат **конкретным items конкретных узлов**. Значения можно задавать фиксированно (**Fixed**) или вычислять из данных (**Expression**). В выражениях применяется синтаксис `{{ ... }}`.

| Выражение | Что возвращает | Важная особенность |
|---|---|---|
| `{{ $json.userId }}` | Поле `userId` **текущего item** | Изменится, если предыдущий узел заменит JSON |
| `{{ $json.body.message }}` | Вложенное поле | В Webhook тело часто находится в `body` |
| `{{ $json.amount * 2 }}` | Вычисленное число | Тип результата важен |
| `{{ $('Example input').item.json.requestId }}` | `requestId` из **связанного** item предыдущего узла | Используется связь исходного и текущего элемента |
| `{{ $('Example input').first().json.requestId }}` | `requestId` **первого** item этого узла | Не заменяет `.item` при множестве item |
| `{{ $('Example input').all().length }}` | Количество items, выданных указанным узлом | Возвращает число; коллекцию нужно обрабатывать осознанно |

Откройте `Get demo user`. В поле URL используется:

```js
{{ 'http://mock-api:8080/users/' + $json.userId }}
```

Попробуйте ID `451`, затем `452`. Перед запросом `$json` содержит `userId`, после запроса `$json` содержит **ответ Mock API** (например, `id`, `name`, `department`). Исходный `requestId` не обязан оставаться в нем.

Затем откройте последний узел `Recall previous node data`. Он намеренно берет одни поля из текущего ответа, а `requestId` — из предыдущего `Example input`. **Задание:** добавьте в этот узел поле `originalDescription` с помощью Expression. Попробуйте не писать выражение вручную: перетащите поле из панели входных данных, если интерфейс его предлагает.

**Особенно важно:** `.item` использует **item linking** — связь текущего элемента с исходным. `.first()` всегда берет первый и может незаметно подставить не того пользователя при обработке коллекции. При перестановке, слиянии или самостоятельном создании items соответствие может нарушаться. [Официальная документация: обращение к предыдущим узлам](https://docs.n8n.io/build/work-with-data/reference-data/reference-previous-nodes/).

## 4. Операторы сравнения и ветвления (10 минут)

**If** делит items на два выхода: `true` и `false`. **Switch** выбирает несколько выходов по правилам. В зависимости от типа поля доступны разные операторы.

| Тип | Операторы (примеры) | Пример |
|---|---|---|
| String | `is equal to`, `contains`, `is empty`, `exists` | `priority` равно `high` |
| Number | `is greater than`, `is greater than or equal to`, `is less than` | `amount >= 100` |
| Boolean | `is true`, `is false` | `approved` истинно |
| Date & Time | `is after`, `is before` | Дата позже заданной |
| Array | `contains`, `length greater than` | Есть ли элемент в списке |

В Tutorial 01 `Is high priority?` проверяет строку, а `Route by department` выбирает `IT`, `Finance` или запасную ветку `Other`.

**Эксперимент 4.1:** выполните три запуска с `userId`: `451`, `452`, `453`. Проверьте маршрут по `department`. Не путайте `department` из API и `type` из исходного обращения.

**Эксперимент 4.2:** в Tutorial 02 откройте `Auto: amount >= 100?`: здесь сравнение именно типа **Number**. Поменяйте порог `100` на `80`. Какие items перейдут в ветку `true`? Верните `100`.

**Самостоятельно:** добавьте в копии одного из If еще одно условие (AND / OR). Например, `amount >= 100` **И** `category = technical`. Сравните AND с OR.

## 5. Коллекции и циклы: почему не нужен for для каждого item (15 минут)

Откройте и запустите **Tutorial 02**. Узел `Create 4 items (example)` заранее создает четыре элемента. Его код приведен только для подготовки тестовых данных; редактировать JavaScript не требуется.

В схеме две независимые учебные ветки:

- **Верхняя: автоматическая обработка.** `Auto: calculate amount` применяет выражение к каждому входному item, а `Auto: amount >= 100?` распределяет элементы по двум выходам. Отдельный явный цикл не нужен: большинство обычных узлов умеет работать со множеством items автоматически.
- **Нижняя: явный цикл.** `Loop: batches of 1` выдает items через выход **loop**, узел `Loop: mark item` обрабатывает текущую порцию и возвращает ее на вход `Loop`. После завершения обработанные items выходят через **done**. Этот вариант полезен, когда нужно ограничить размер пакета, последовательно выполнять запросы или вставить ожидание.

**Эксперимент 5.1:** посмотрите Output источника: **4 items**. Затем Input/Output у `Auto: calculate amount`: столько же items, но добавлено вычисленное поле.

**Эксперимент 5.2:** в нижней ветке проверьте, сколько раз исполнился `Loop: mark item`. Поменяйте **Batch Size** с `1` на `2` и повторите запуск. Сколько порций получилось?

**Эксперимент 5.3:** откройте выход **done** у `Loop: batches of 1`: в отличие от `loop`, это результат после завершения итераций. Для самопроверки сравните количество обработанных элементов.

> Отличие: **список внутри одного JSON** (`{"tickets":[...]}`) — не то же самое, что **несколько items**. Для разделения одного массива на items есть узел **Split Out**. Обратная задача — сбор элементов в итоговую структуру — решается **Aggregate** или обработкой списка в Code. В рамках практикума достаточно понять разницу, писать код для агрегации не требуется.

## 6. Триггеры, Webhook и ответы (10 минут)

**Manual Trigger** запускается из редактора. **Webhook** запускается запросом извне. **Schedule Trigger** — по расписанию (для автоматических запусков нужен опубликованный workflow). **Error Trigger** позволяет построить **отдельный** процесс уведомления об ошибках.

Импортируйте Tutorial 03 и откройте `Webhook: tutorial-ping`.

1. Выберите **Test URL** и запустите ожидание входящего события (**Listen for Test Event** / **Execute workflow**).
2. В PowerShell выполните (не используйте Linux-версию `curl` с одинарными кавычками):

```powershell
$body = @{ message = 'Hello n8n'; sender = 'student' } | ConvertTo-Json
Invoke-RestMethod -Uri 'http://localhost:5678/webhook-test/tutorial-ping' -Method Post -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($body))
```

3. Проверьте Input узла Webhook: тело запроса находится в `$json.body`. Затем посмотрите результат `Map incoming body` и HTTP-ответ узла `Respond demo (HTTP 200)`.
4. Измените `message` и повторите опыт, заново включив ожидание тестового Webhook, если оно закончилось.

**Что важно:** Test URL работает только в режиме ожидания тестового события, а Production URL вида `/webhook/tutorial-ping` — после публикации. Не путайте `/tutorial-ping` с `/support-request` из основного задания. Для работы с Production URL смотрите вкладку **Executions**, а не ожидание подсветки узлов на полотне.

**Необязательный опыт:** самостоятельно создайте новый пустой workflow с **Schedule Trigger** и интервалом в несколько минут, затем добавьте **Edit Fields**. После эксперимента снимите workflow с публикации. Не нужно ждать фактического срабатывания для прохождения основной работы.

## 7. Что еще есть в n8n (обзор, без обязательной настройки)

| Узел | Когда полезен |
|---|---|
| **Filter** | Удалить items, не проходящие условие, без отдельной ветки false |
| **Merge** | Объединить данные нескольких веток; необходимо понимать режим объединения |
| **Wait** | Сделать паузу до продолжения; полезно в контролируемых повторных попытках |
| **Split Out / Aggregate** | Преобразовать массив ↔ набор items |
| **Code** | Добавить произвольную логику, когда стандартных узлов недостаточно |
| **Stop And Error / error output** | Явно завершить выполнение с ошибкой или обработать сбой узла |

**Дополнительные задания основного ДЗ:** Retry и защита от повторной регистрации. Этот практикум намеренно **не показывает готовый Retry-workflow**: метод решения требуется выбрать самостоятельно.

## 8. Самопроверка и типичные ошибки (5 минут)

Проверьте себя без подсказок:

1. Какие варианты запуска n8n вы знаете и в каких случаях подходит Webhook вместо Manual Trigger?
2. Чем `{{ $json.userId }}` отличается от `{{ $('Example input').item.json.userId }}`?
3. Почему после HTTP Request поле из исходного Edit Fields может исчезнуть из `$json`?
4. Для чего нужны `.first()` и `.all()`? Почему `.first()` не означает «текущий item»?
5. Как задать сравнение Number `amount >= 100`? Чем Number `100` отличается от String `"100"`?
6. Как n8n обработает четыре входных items в Edit Fields без явного цикла?
7. Как работают выходы `loop` и `done` у Loop Over Items?
8. Где искать ошибку, если HTTP Request возвращает 404?
9. Почему `localhost:8080` внутри контейнера n8n не указывает на Mock API?
10. Как отправить тестовое событие на `/webhook-test/tutorial-ping` и чем оно отличается от Production URL?

### Диагностика проблем

| Симптом | Что проверить |
|---|---|
| «Field is undefined» | Откройте Input **этого** узла, проверьте путь поля в JSON |
| После HTTP Request пропали поля | Используйте обращение к предыдущему узлу / осознанно объедините данные |
| Вместо четырех item только один | Возможно, это массив внутри одного JSON; проверьте Split Out |
| Цикл не завершается | Проверьте обратное соединение, ветку `done` и наличие условия завершения для ручных циклов |
| Webhook 404 not registered | Проверьте тестовый режим или публикацию workflow и правильный URL |
| HTTP Request не находит `localhost:8080` | Используйте внутренний адрес `http://mock-api:8080` |

**Следующий шаг:** откройте [ASSIGNMENT.md](ASSIGNMENT.md) и импортируйте `workflows/student-starter.json` в **новый** workflow. Учебные workflow не являются частью итоговой сдачи и не должны подменять рабочий `/support-request`.
