# Быстрый практикум: основы n8n (этап 2)

Начните с импорта `workflows/tutorial-basics.json` по инструкции [SETUP.md](SETUP.md). Учебный workflow показывает возможности платформы на простом наборе данных и не является решением ДЗ.

## 1. Manual Trigger и Execution

**Manual Trigger** запускает пример вручную. Нажмите **Execute workflow** и посмотрите, какие узлы были выполнены (подсвечены). Каждый запуск называется *execution*.

## 2. Edit Fields: работа с JSON

Узел **Example input** создает пример объекта: `requestId`, `userId`, `priority` и т.д. Двойной щелчок по узлу открывает параметры, а панель Input/Output показывает JSON до и после обработки.

В узлах **Priority = high** и **Priority = other** к данным добавляется строковое поле `exampleBranch`. Включено сохранение остальных входных полей.

## 3. Expressions: динамические значения

В HTTP Request указан URL в виде выражения:

```javascript
{{ 'http://mock-api:8080/users/' + $json.userId }}
```

`$json.userId` берется из данных предыдущего узла. Поменяйте ID пользователя и убедитесь, что URL меняется без редактирования HTTP Request.

## 4. If: две ветви

**Is high priority?** проверяет `priority === 'high'`. Истинная ветвь идет к **Priority = high**, ложная - к **Priority = other**. Поменяйте `priority` на `medium` и сравните execution.

## 5. HTTP Request: обращение к сервису

**Get demo user** запрашивает пользователя из Mock API по HTTP GET. На этапе 2 доступны `451`, `452` и `453`. Посмотрите статус вызова и JSON ответа. Попробуйте адрес `http://127.0.0.1:8080/users/451` в браузере (адрес для **хоста**, не контейнера).

После HTTP Request входная структура может измениться: ответ Mock API становится текущими данными для следующего узла. Это важное отличие от обычной передачи параметров функции.

## 6. Switch: несколько направлений

**Route by department** распределяет ответы Mock API по `department`: IT, Finance либо fallback **Other**. Запустите пример с `userId = 451`, затем `452`, затем `453` и проверьте, какие выходы срабатывают.

## 7. Sticky Note: оформление

Sticky Notes рядом с группами узлов объясняют, что происходит. В своем основном задании используйте их для описания нетривиальных веток и ошибок. Названия узлов должны отражать назначение операции.

## Мини-практика

1. Поменяйте `userId` на `452`. Ожидайте маршрут Finance.
2. Поменяйте `priority` на `medium`. Ожидайте false-ветвь If.
3. Поменяйте `userId` на `453`. Ожидайте fallback-ветвь Switch.
4. Откройте Input/Output всех выполненных узлов и объясните, почему после HTTP Request текущий JSON отличается от исходного.
5. Верните настройки к исходным и сохраните workflow.

## Что будет в основном ДЗ

Позднее вам предстоит **создать свой отдельный workflow**, принимающий обращения через Webhook, проверяющий данные и регистрирующий результат. Данный пример служит только для знакомства с визуальными узлами, expressions и HTTP.
