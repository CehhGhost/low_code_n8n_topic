# Проверка этапа 2

**Статус:** готов технический прототип обучающего окружения, но **не подтвержден end-to-end запуск в Docker / импорт в n8n**. Это нужно проверить на машине с Docker перед выдачей студентам.

## Что проверено автоматически

Команда из корня репозитория:

```bash
python -m unittest discover -s tests -v
```

На этапе 2 подготовлены 7 проверок без сторонних Python-пакетов:

- `/health` отвечает JSON и HTTP 200;
- три тестовых пользователя доступны через `/users/{id}`;
- неизвестный пользователь получает HTTP 404 и `USER_NOT_FOUND`;
- неготовый `POST /requests` честно отвечает HTTP 501;
- JSON учебного workflow содержит нужные типы узлов, но не содержит webhook основного ДЗ;
- все соединения JSON указывают на существующие узлы;
- HTTP Request использует внутренний адрес Docker DNS `mock-api:8080`.

Эти проверки **не гарантируют**, что параметры узлов совместимы с конкретной версией n8n, что n8n откроет JSON в редакторе или что Docker Compose запускается без ошибок.

## Что нужно проверить вручную на машине с Docker

- [ ] `docker compose config` выводит конфигурацию без ошибок.
- [ ] `docker compose up -d` успешно запускает оба сервиса.
- [ ] `docker compose ps` показывает здоровый `mock-api` и работающий `n8n`.
- [ ] `http://127.0.0.1:8080/users/451` возвращает Иван Иванов, department IT.
- [ ] `http://localhost:5678` открывает мастер первого запуска.
- [ ] Импорт `workflows/tutorial-basics.json` завершается без ошибок.
- [ ] Запуск example с `userId=451`, `priority=high` попадает в ветку True и IT.
- [ ] Запуск с `userId=452`, `priority=medium` попадает в ветку False и Finance.
- [ ] Запуск с `userId=453` попадает в ветку Other у Switch.
- [ ] Данные и workflow переживают `docker compose down && docker compose up -d`.

Если один из пунктов не работает, необходимо исправить исходные файлы и повторить проверку до перехода к основному заданию.
