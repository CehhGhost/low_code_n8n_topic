# Проверка этапа 3: Mock API

**Цель:** убедиться, что учебный API реализует контракт и умеет имитировать ситуации для будущих автотестов студенческих workflow. Этот этап не включает проверку самого студенческого Webhook: его еще предстоит реализовать.

## 1. Проверки исходного кода без Docker

Из корня репозитория:

```bash
python -m unittest discover -s tests -p 'test_*.py' -v
```

Проверяются структура учебного workflow, ответы пользователей, регистрация, валидация JSON, чтение записей, дубликаты, изоляция тестовых запросов, имитация временных и постоянных ошибок, reset и журнал вызовов.

**Результат разработки этапа 3:** 25 тестов пройдено в среде автора (Python; без запуска Docker).

Важно: `tests/test_stage3_mock_api.py` тестирует **наш вспомогательный сервер**, а не оценивает workflow студента. Баллы за ДЗ по нему не начисляются.

## 2. Запуск обновленного контейнера

Для нового клона:

```bash
docker compose up -d
```

Если этап 2 уже запущен и файлы были заменены на новые, необходимо перезапустить Python-сервер, чтобы он загрузил новую версию кода:

```bash
docker compose restart mock-api
```

Проверьте:

```bash
docker compose ps
```

Страница `http://127.0.0.1:8080/health` должна вернуть `{"status":"ok","stage":3}`.

## 3. Smoke-тест на **реально работающем** контейнере

```bash
python tests/smoke_mock_api.py
```

Проверяет через HTTP 6 этапов: `/health`, чтение пользователя, регистрацию и чтение обращения, последовательность двух ошибок `503` с последующим успехом, журнал вызовов и сброс состояния.

**Внимание:** smoke-тест стирает только временные данные Mock API и настройки искусственных ошибок. Он не меняет сохраненные workflow в n8n. Не запускайте его одновременно с другими проверками или во время демонстрации существующих записей.

## 4. Что еще стоит проверить вручную

- [ ] n8n на `http://localhost:5678` по-прежнему открывается.
- [ ] Старый учебный workflow успешно выполняет `GET http://mock-api:8080/users/451`.
- [ ] `GET http://127.0.0.1:8080/__test__/records` возвращает JSON с ключом `records`.
- [ ] Служебные endpoints недоступны из интернета (порты привязаны к `127.0.0.1`).
- [ ] `docker compose down` и повторный запуск не удаляют данные n8n, а Mock API намеренно сбрасывает свои данные при перезапуске.

## 5. Граница готовности

| Компонент | Состояние |
|---|---|
| Mock API | Реализован и покрыт автоматическими тестами |
| Имитация сбоев и учет повторных запросов | Реализованы |
| Учебный workflow | Без изменений; содержание пересмотрим позже |
| Основной студенческий workflow | Не реализован (следующий этап) |
