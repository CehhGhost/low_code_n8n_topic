# Локальный запуск учебного окружения

## Требования

- Docker Desktop с работающим Docker Engine и Docker Compose v2 (Windows/macOS) или Docker Engine + плагин Compose (Linux).
- Свободные порты **5678** (n8n) и **8080** (Mock API) на `127.0.0.1`.
- Интернет нужен **один раз** для загрузки образов Docker, после этого учебный пример не обращается к публичным API.

## Запуск

В терминале из корня проекта:

```bash
docker compose up -d
```

Если требуется отслеживать события запуска:

```bash
docker compose ps
docker compose logs -f n8n
```

Открой **http://localhost:5678**. При первом запуске создай **локальную** учетную запись владельца (owner). Все работает локально, данные никуда не отправляются.

Проверка Mock API в браузере: **http://127.0.0.1:8080/users/451**. Ожидается JSON с пользователем Иван Иванов.

## Проверка готового Mock API

После запуска сервисов можно проверить, что Mock API поддерживает регистрацию обращений и имитацию ошибок:

```bash
python tests/smoke_mock_api.py
```

Smoke-тест временно очищает данные Mock API, поэтому выполняй его отдельно от других экспериментов.

## Импорт учебных workflow

1. Создай новый workflow в веб-интерфейсе n8n.
2. Открой меню workflow (три точки) и выбери **Import from File**.
3. Выбери файл `workflows/tutorial-basics.json`.
4. Сохрани workflow и запусти его через **Execute workflow**.
5. Затем отдельно импортируй `workflows/tutorial-items-loops.json` и `workflows/tutorial-webhook.json`.
6. Выполни опыты из [N8N_BASICS.md](N8N_BASICS.md) последовательно. Обрати внимание на примеры работы с предыдущими узлами, несколько items, Loop Over Items и тестовый Webhook.

**Важно:** учебные workflow не содержат Webhook приема обращений по пути `/support-request`, регистрацию заявок, обработку ошибок и экспертные дополнения. Они лишь показывают основные узлы и принципы передачи данных. После практикума изучи [ASSIGNMENT.md](ASSIGNMENT.md) и импортируй `workflows/student-starter.json` как отдельный workflow.

## Адреса внутри и снаружи контейнеров

| Где выполняется запрос | Адрес |
|---|---|
| Браузер компьютера → n8n | `http://localhost:5678` |
| Компьютер → Mock API | `http://127.0.0.1:8080/users/451` |
| Узел HTTP Request внутри n8n → Mock API | `http://mock-api:8080/users/451` |

**`localhost` внутри контейнера n8n указывает на сам контейнер n8n, а не на Mock API.**

## Остановка / повторный запуск

```bash
docker compose down        # Останавливает контейнеры, сохраненные workflow остаются в volume

docker compose up -d       # Повторный запуск
```

Не используй `docker compose down -v`, если хочешь сохранить работу: эта команда удаляет volume с данными n8n.

## Частые проблемы

| Симптом | Возможная причина / решение |
|---|---|
| `docker` не найден | Установите Docker Desktop (или Docker Engine + Compose) и запустите Docker |
| Порт `5678` занят | Закройте конфликтующий сервис или измените маппинг порта в `compose.yaml` и актуализируйте ссылки в инструкциях |
| Страница не открывается | Выполните `docker compose ps` и `docker compose logs n8n` |
| В HTTP Request написано `ECONNREFUSED` | Проверьте `docker compose ps` и адрес `http://mock-api:8080` внутри workflow |
| Запрос в API возвращает 404 | Проверьте путь и ID: пользователи только 451/452/453, несуществующие обращения возвращают `REQUEST_NOT_FOUND` |
| Запрошено создать owner | Обычный первый запуск локального n8n; создайте учетную запись |

## Безопасность

Это **локальная лабораторная конфигурация**, не подходящая для публичного сервера. Порты доступны только с этого компьютера. `N8N_SECURE_COOKIE=false` допустимо здесь лишь потому, что лабораторное окружение использует локальный HTTP. Однако все равно лучше не помещай реальные секреты в учебный workflow.

Официальные источники: [n8n: установка с Docker Compose](https://docs.n8n.io/hosting/installation/server-setups/docker-compose/), [Импорт и экспорт workflow](https://docs.n8n.io/workflows/export-import/).
