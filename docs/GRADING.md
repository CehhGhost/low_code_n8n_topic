# Критерии оценивания: n8n Workflow Lab

> Согласованная модель оценивания. Баллы за функциональность привязаны к конкретным проверкам в [`TEST_CASES.md`](TEST_CASES.md); формат запросов и ответов зафиксирован в [`API_CONTRACT.md`](API_CONTRACT.md).

## Общие правила

- Базовое задание одинаково для всех студентов. Уровни **Б**, **Б+** и **П** различаются качеством выполнения, а не разным списком функций.
- За базовое задание можно получить **100 баллов**.
- **Видеоотчет обязателен**: без доступного видео работа считается неполной и возвращается на дооформление, независимо от баллов за техническую часть.
- При выставлении баллов оцениваются конкретные проверяемые результаты, а не только количество узлов в n8n.
- Уровень **Э** присваивается только при выполнении условий **П** и обоих дополнительных заданий.

**Принцип:** каждый критерий разбит на конкретные тест-группы в [`TEST_CASES.md`](TEST_CASES.md). Баллы за группу начисляются только при прохождении всех входящих в нее сценариев. Вес отдельной группы: `VAL-01...04` — по 3; `USR-01...02` — по 4; `ROUTE-01...04` — по 3; `SLA-01...03` — по 3; `REG-01` — 4, `REG-02` — 3, `REG-03` — 2; `ERR-01...02` — по 5.

## Уровни оценивания

| Уровень | Условие |
|---|---|
| **Б** | 60–74 балла, основной сценарий работает, видео и отчет представлены |
| **Б+** | 75–89 баллов; также максимальный уровень, если баллов 90+, но обязательные функциональные проверки пройдены не полностью |
| **П** | 90–100 баллов, **60/60** за функциональность и не менее **20/25** за видео |
| **Э** | Выполнены условия **П** и пройдены все проверки **обоих** дополнительных заданий |

Менее 60 баллов — ниже уровня **Б**. Отсутствие обязательного видео — **сдача не завершена**; итоговый уровень до предоставления видео не выставляется.

## Дополнительные задания для уровня Э

### А. Retry при временной ошибке

1. При `503 → успех` выполнение завершается успешно после повтора.
2. При `503 → 503 → успех` выполнение завершается успешно после повторов.
3. При постоянном `503` число попыток ограничено; процесс завершается корректно.
4. При постоянной ошибке, например `400`, повторов нет.

Способ реализации студент выбирает самостоятельно; готовый механизм Retry в обучающем workflow не предоставляется.

### Б. Защита от повторной регистрации

1. Повторный запрос с тем же `requestId` **не создает вторую запись**.
2. Workflow корректно сообщает, что обращение уже зарегистрировано.

Для задания проверяются **последовательные** повторы; защита от одновременных конкурентных запросов не требуется.

Все перечисленные проверки дополнительных заданий должны проходить для получения **Э**. Выполнение дополнительной части показывается в видеоотчете.
