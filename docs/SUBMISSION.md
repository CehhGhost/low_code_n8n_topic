# Как сдать лабораторную работу

Сдача состоит из **экспортированного workflow, письменного отчета и обязательного видеоотчета**. Все это связывается в одном Pull Request (PR) в репозитории экспертов.

| Артефакт | Где находится |
|---|---|
| Основное решение (JSON) | `submissions/support-request-workflow.json` |
| Отчет | `REPORT.md` |
| Видеоотчет | Ссылка в `REPORT.md` и в описании PR |
| Результаты базовых тестов | `REPORT.md`, при необходимости кратко в PR |
| Результаты экспертных тестов (если Э) | `REPORT.md` и видео |

## 1. Подготовьте свою копию репозитория

1. Открой GitHub-репозиторий задания по ссылке.
2. Создай fork в свой аккаунт GitHub.
3. Клонируй свой fork любым способом, например через **Code → HTTPS → Copy URL** и `git clone <ТВОЙ-FORK>`.
4. Создай отдельную ветку, например:

```shell
git switch -c solution/n8n-lab
```

## 2. Выполни задание и проверь работу

Прочитай [ASSIGNMENT.md](ASSIGNMENT.md), создай и **опубликуй** в n8n собственный workflow. Запусти:

```shell
python tests/run_tests.py --mode base
```

Для уровня Э дополнительно:

```shell
python tests/run_tests.py --mode expert
```

Тестовый раннер создает `reports/latest-results.md` и `reports/latest-results.json`. Они **не включены в Git**: основные числа и ошибки перенеси в `REPORT.md`. Непройденные проверки нужно также перечислить, если таковые имеются.

## 3. Экспортируй workflow

1. Открой **основной** workflow в редакторе n8n (не обучающий пример).
2. Сохрани последние изменения и убедись, что они проверены.
3. В меню workflow выбери экспорт/скачивание JSON (название пункта зависит от версии интерфейса).
4. Сохрани файл как `submissions/support-request-workflow.json`.
5. Перед сдачей проверь, что файл действительно содержит твои узлы и может импортироваться обратно в n8n.

**Предупреждение:** экспорт может содержать конфигурацию узлов и ссылки на учетные данные. В работе не нужны реальные токены. Не добавляй в JSON, README, отчет или PR пароли, токены, cookies и персональные данные.

## 4. Заполните письменный отчет

Открой [`REPORT.md`](../REPORT.md) и внеси реальные результаты:

- какие части выполнены, какие нет.
- функциональная оценка `X/60`, перечень непройденных ID.
- итог экспертных тестов (если выполнялись).
- причины основных технических решений.
- возникшие проблемы и ограничения.
- фактически потраченное время, **включая запись видео**.
- ссылку на видео и его длительность.

Отчет должен соответствовать **той же версии workflow**, которую вы прикладываете.

## 5. Запиши обязательный видеоотчет

Рекомендуемая длительность - **около 4 минут**, допустимый ориентир **3-6 минут**. Запиши экран с кратким голосовым комментарием либо понятными текстовыми пояснениями (формат можно дополнительно согласовать с экспертами).

| Примерное время | Что показать | Баллы |
|---|---|---:|
| 0:00–0:40 | Общая структура и смысл основных веток | 4 |
| 0:40–1:40 | Успешное обращение: вход, выполнение, реальная регистрация | 6 |
| 1:40–2:20 | Некорректное обращение или сбой API | 5 |
| 2:20–3:20 | Почему выбраны такие узлы, как передаются данные | 6 |
| 3:20–4:00 | Команда тестов и интерпретация результата | 4 |

Если заявляешь Э, дополнительно продемонстрируй логику Retry и отсутствие повторной регистрации, ролик может быть ближе к верхней границе. Для подтверждения регистрации можно показать запись в `GET /__test__/records`, но не нужно объяснять внутреннюю реализацию Mock API.

Помести видео в хранилище или на видеохостинг с **доступом по ссылке**, вставь URL в `REPORT.md` и описание PR. Обязательно открой ссылку в приватном окне браузера, чтобы убедиться, что эксперт сможет просмотреть запись. **Если видео отсутствует или недоступно, работа возвращается как неполная и итоговый уровень не выставляется**, независимо от тестов.

## 6. Создай Pull Request

Убедись, что изменяются только файлы сдачи. Базовый вариант:

```shell
git status --short
git add submissions/support-request-workflow.json REPORT.md
git commit -m "Complete n8n support request workflow"
git push -u origin solution/low_code_n8n_topic
```

На GitHub своего fork создай PR из `solution/low_code_n8n_topic` в `main` **исходного репозитория задания**. Заполни шаблон PR. Добавь ссылку на видео и краткий результат тестов. Если изменял другие файлы для реализации, опиши необходимость изменений, изменять `mock-api/` и исходные `tests/` ради обхода проверок **запрещено**.

## 7. Если эксперт попросил исправления

Внеси изменения в workflow, заново экспортируйте JSON, повтори проверки и при необходимости перезапиши видео. Обнови `REPORT.md`, сохрани коммит и отправь изменения в ту же ветку: PR обновится автоматически.

## Самопроверка перед сдачей

- [ ] В PR есть **основной** workflow.
- [ ] JSON можно импортировать в n8n, webhook имеет путь `support-request`.
- [ ] `REPORT.md` заполнен по реальным результатам, известные ошибки перечислены.
- [ ] Видео доступно без дополнительного одобрения и показывает результаты тестов.
- [ ] Видео и отчет соответствуют коду в PR.
- [ ] В PR нет ключей, данных n8n и файлов из локального Docker volume.
- [ ] Для Э: оба дополнительных задания и все 8 экспертных проверок.
