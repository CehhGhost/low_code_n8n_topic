# n8n Workflow Lab

**Тема:** Low-code автоматизация бизнес-процессов и интеграция информационных систем на примере n8n.  
**Формат:** самостоятельная лабораторная работа с готовым окружением, автотестами и обязательным видеоотчетом.  
**Трудоемкость:** ориентировочно 7–8 часов для обязательной части, до 10–11 часов с дополнениями; **не более 12 астрономических часов, включая отчет и видео**.

## Контекст и результат

Представьте, что служба поддержки получает обращения, а информация о пользователях и регистрация заявок находятся в разных сервисах. Вам нужно связать их с помощью визуального workflow в **n8n**, не создавая отдельный backend. Система должна принять обращение, проверить поля, найти пользователя через REST API, определить ответственную группу и SLA, зарегистрировать обращение и вернуть JSON с результатом. При сбоях — вернуть корректную ошибку.

В ходе работы вы познакомитесь с **Manual Trigger, Edit Fields, If, Switch, expressions, HTTP Request, Webhook, Loop Over Items** и отладкой workflow. Для экспертного уровня предусмотрены самостоятельные задачи по **Retry** и **защите от повторной регистрации**.

## Необходимые инструменты

- Docker Desktop / Docker Engine с Compose v2;
- Python 3.10 или новее для запуска **готовых** тестов;
- браузер и Git (GitHub для финальной сдачи).

**Платные подписки, n8n Cloud, LLM API и написание серверного кода не требуются.** Интернет нужен для первоначальной загрузки Docker-образов.

## Быстрый запуск

```shell
docker compose up -d
```

После запуска:

- n8n: http://localhost:5678 (при первом запуске создайте локальный аккаунт);
- Mock API: http://127.0.0.1:8080/health;
- пример пользователя: http://127.0.0.1:8080/users/451.

В n8n по очереди импортируйте **три учебных workflow**: `workflows/tutorial-basics.json`, `workflows/tutorial-items-loops.json`, `workflows/tutorial-webhook.json` и выполните упражнения из [практикума](docs/N8N_BASICS.md). Затем в **отдельный** workflow импортируйте `workflows/student-starter.json` и реализуйте [основное ДЗ](docs/ASSIGNMENT.md).

**Важно:** рабочий Webhook должен иметь метод `POST` и путь `support-request`. Тесты обращаются к **Production URL** `http://localhost:5678/webhook/support-request`; необходимо сохранить и **опубликовать** workflow. Если существуют два workflow с одинаковым путем, опубликован должен быть только один.

## Что должно получиться

**Вход:**

```json
{"requestId":"REQ-1024","userId":451,"type":"technical","priority":"high","description":"Не работает авторизация"}
```

**Успешный ответ HTTP 201:**

```json
{"requestId":"REQ-1024","status":"registered","assignedGroup":"Technical Support","slaHours":1,"userName":"Иван Иванов"}
```

Обращение должно реально сохраниться в Mock API, а не только вернуться в HTTP-ответе. Для ошибок входа/внешних сервисов предусмотрены HTTP 400, 404 и 502 согласно [контракту](docs/API_CONTRACT.md).

## Автоматические проверки

Из **корня проекта**:

```shell
python tests/run_tests.py --mode base
```

Для экспертных дополнений:

```shell
python tests/run_tests.py --mode expert
```

Результаты сохраняются в `reports/latest-results.md` и `reports/latest-results.json`. **Тестовый раннер сбрасывает состояние Mock API** перед сценариями; не выполняйте параллельно ручные запросы.

Функциональная часть оценивается **18 группами на 60 баллов**. Остальные баллы выставляются экспертом: **25 за обязательное видео**, 10 за письменный отчет, 5 за оформление схемы. **Б / Б+ / П** зависят от качества одного и того же базового задания; **Э** требует уровня П и всех 8 экспертных проверок. При отсутствии доступного видео сдача не завершена.

## Структура репозитория

```text
n8n-workflow-lab/
├── compose.yaml                # готовые n8n и Mock API
├── workflows/
│   ├── tutorial-basics.json       # данные, expressions, If/Switch, HTTP
│   ├── tutorial-items-loops.json  # несколько items, циклы
│   ├── tutorial-webhook.json      # вебхуки и HTTP-ответы
│   └── student-starter.json    # заготовка основного задания
├── mock-api/server.py          # готовый имитатор внешних систем
├── tests/run_tests.py          # проверка результата через HTTP
├── docs/
│   ├── ASSIGNMENT.md           # постановка
│   ├── API_CONTRACT.md         # вход, выход, HTTP API
│   ├── N8N_BASICS.md           # практикум
│   ├── SETUP.md                # окружение
│   ├── TEST_RUNNER.md          # запуск проверок
│   ├── TEST_CASES.md           # тесты и баллы
│   ├── GRADING.md              # критерии оценивания
│   └── SUBMISSION.md           # сдача работы
├── submissions/                # сюда положить экспорт собственного workflow
├── REPORT.md                   # шаблон письменного отчета
└── .github/pull_request_template.md
```

Готовое решение эксперта в **публичный** репозиторий не входит. Для выполнения ДЗ нельзя изменять Mock API или исходные автотесты с целью обхода требований.

## Сдача

Подготовьте экспорт **своего** workflow `submissions/support-request-workflow.json`, заполните `REPORT.md`, запишите видеоотчет с успешным и ошибочным сценариями, запустите тесты и создайте Pull Request. Все шаги: [SUBMISSION.md](docs/SUBMISSION.md).

## Типичные проблемы

| Симптом | Что проверить |
|---|---|
| Webhook отвечает 404 «not registered» | Сохранен ли и опубликован ли нужный workflow; используете ли Production URL |
| Ответ содержит `TODO` | Выполняется стартовая заготовка, основная логика еще не реализована |
| Mock API не отвечает из HTTP Request | В контейнере нужен `http://mock-api:8080`, не `localhost:8080` |
| Тесты не находят регистрацию | Действительно ли был вызван `POST /requests` с правильными полями |
| После перезапуска пропали обращения | Mock API хранит тестовые записи в памяти, это ожидаемо |
| Перестали работать все тесты после импорта | Проверьте, какой из workflow сейчас опубликован |

Подробнее: [SETUP.md](docs/SETUP.md) и [TEST_RUNNER.md](docs/TEST_RUNNER.md).

## О работе с данными

Это локальное учебное окружение. Не публикуйте его во внешней сети, не добавляйте реальные пользовательские данные, токены и учетные данные в экспорт workflow или в Git. Не выполняйте `docker compose down -v`, если хотите сохранить локальные workflow.
