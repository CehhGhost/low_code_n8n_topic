# n8n Workflow Lab

**Тема:** Low-code автоматизация бизнес-процессов и интеграция информационных систем на примере n8n.

Студенту предстоит создать workflow для обработки обращений: Webhook принимает JSON, workflow проверяет данные, получает информацию о пользователе, назначает группу поддержки и SLA, регистрирует обращение через API и корректно обрабатывает ошибки. Дополнительные задачи для уровня Э - Retry при временных сбоях и защита от повторной регистрации.

**Модель оценки:** Б / Б+ / П по качеству выполнения одного базового задания; Э - уровень П и оба дополнительных задания. За базовое задание 100 баллов (60 - функциональность, 25 - обязательный видеоотчет, 10 - письменный отчет, 5 - оформление workflow).

> **Статус: этап 3 - рабочий Mock API.** Учебный workflow пока оставлен из этапа 2: его содержание будет пересмотрено позже. Эталонный workflow основного ДЗ, заготовка для самостоятельного выполнения, автоматическая оценка работ и инструкции по сдаче еще впереди. **Не публиковать в качестве готового задания для студентов.**

## Быстрый старт

Нужен Docker Engine / Docker Desktop с Docker Compose v2.

```bash
docker compose up -d
```

- **n8n:** http://localhost:5678 - создать локального владельца при первом запуске.
- **Mock API:** http://127.0.0.1:8080/health - ожидать `{"status":"ok","stage":3}`.
- **Тестовые пользователи:** http://127.0.0.1:8080/users/451, `/users/452`, `/users/453`.
- **Обучение:** импортировать [`workflows/tutorial-basics.json`](workflows/tutorial-basics.json) в n8n и выполнить пример.

Если этап 2 уже запущен, а вы обновили только файлы репозитория:

```bash
docker compose restart mock-api
```

### Проверка новой версии

```bash
# Тесты кода Mock API и структуры обучающего workflow (без Docker)
python -m unittest discover -s tests -p 'test_*.py' -v

# Проверка HTTP API внутри реально запущенного контейнера
python tests/smoke_mock_api.py
```

Второй тест очищает временные записи и искусственные сбои **Mock API**, но не workflow n8n. Не выполняйте его одновременно с другими тестами.

## Архитектура

- `n8n` (Community Edition) и `mock-api` работают в одной Docker-сети.
- **Из n8n:** запросы к `http://mock-api:8080`.
- **С компьютера:** запросы к `http://127.0.0.1:8080`.
- Данные n8n сохраняются в Docker volume; записи Mock API хранятся **только в оперативной памяти**, поэтому после его перезапуска исчезают.
- Порты привязаны к loopback интерфейсу `127.0.0.1`. Это учебная конфигурация, не предназначенная для публичного размещения.
- Для основной части не нужны платные подписки или внешние API.
